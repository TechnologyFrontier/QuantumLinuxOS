# 1. 製品範囲と位置づけ

量子OSを「標準版」と「デスクトップ版」の2つの版で提供する。標準版は QOS-BD 0.1 のとおり GUI を持たない。デスクトップ版は同じ量子サービス・CLI・更新方式の上に GNOME デスクトップを載せ、汎用デスクトップとして Ubuntu と同等の日常利用を可能にしたうえで、次の点で上回ることを目標とする。

| **観点** | **デスクトップ版の方針** |
|---|---|
| 壊れない OS | 読み取り専用ルートと A/B 更新（署名検証・試行起動・自動切り戻し）をデスクトップ全体に適用する。更新の失敗で起動不能にならない。 |
| 量子計算の標準搭載 | 量子サービスに加え、回路の作成・図示・実行・結果のグラフ表示を行う GUI アプリを標準搭載する。 |
| GUI での安全な保守 | 更新状態の確認・更新バンドルの適用・切り戻し状況の表示を、管理者認証付きの GUI で行う。 |
| アプリの追加 | OS 本体を書き換えずにアプリを追加できるよう、Flatpak を標準搭載する（導入先は状態領域）。 |
| 開発環境 | 量子回路の開発環境（IntelliJ IDEA と量子OSプラグイン）の導入を支援する。 |

Ubuntu と同等の汎用機能（ブラウザー、ファイル管理、日本語入力、ネットワーク設定など）は Debian の既存パッケージを再利用し、新規開発しない。

## 1.1 対象外

ディスク暗号化、Secure Boot、複数アーキテクチャー、リモートデスクトップ、量子実機、クラウド実行は初版の対象外とする。IntelliJ IDEA 本体は JetBrains の利用規約上の再配布条件が未確認のため、OS イメージに同梱しない。

# 2. 構成と読み取り専用ルートとの両立

## 2.1 版の作り分け

イメージ作成スクリプトに「版」（`QOS_EDITION`）を導入する。版ごとの差分は `image/editions/<版>/` に置き、標準版の手順・出力は変更しない。

| **項目** | **標準版（standard）** | **デスクトップ版（desktop）** |
|---|---|---|
| パッケージ | `image/packages.txt` | 標準版＋`image/editions/desktop/packages.txt` |
| 製品 ID（更新バンドル） | `quantumos` | `quantumos-desktop`（標準版のバンドルを誤適用しない） |
| ルートスロット／イメージ | 6 GiB／3 GiB | 12 GiB／9 GiB（暫定、実測で見直す） |
| 推奨ディスク | 32 GiB 以上 | 64 GiB 以上 |
| 既定ターゲット | multi-user | graphical（GDM） |
| 健全性確認 | QOS-FD の 6 項目 | 標準版の tty1 コンソールを表示マネージャー（GDM）の稼働に置き換えた 6 項目（GDM が tty1 を使うため） |

## 2.2 読み取り専用ルートでの GNOME

| **書き込み先** | **扱い** |
|---|---|
| 利用者ホーム | `/home` → `/var/home`（状態領域）。標準版と同じ。 |
| システム設定（利用者追加、ネットワーク、ロケール等） | `/etc` オーバーレイの上位層（状態領域）。 |
| 追加アプリ | Flatpak のシステム導入先 `/var/lib/flatpak`（状態領域）。更新・切り戻しの影響を受けない。 |
| apt によるパッケージ追加 | 行わない（ルートは読み取り専用）。OS の構成変更は更新バンドルで配布する。GNOME ソフトウェアは Flatpak 専用とし、PackageKit は無効化（mask）する。 |

## 2.3 量子サービスの利用権限

標準版と同じく `quantum` グループの利用者だけが量子サービスを使える。デスクトップ版では、GNOME の初期設定（gnome-initial-setup）や「ユーザー」設定で作成した利用者を自動で `quantum` グループに加える。Debian の accountsservice は利用者の作成に adduser を使うため、`/etc/adduser.conf` に `EXTRA_GROUPS="users quantum"`、`ADD_EXTRA_GROUPS=1` を設定する。管理者権限（sudo グループ）の有無は GNOME の設定に従う。

# 3. 量子アプリと GUI 保守（DT-01〜DT-05）

| **機能ID** | **名称** | **内容** |
|---|---|---|
| DT-01 | デスクトップ版イメージ | GNOME（gnome-core）、GDM、日本語環境（ロケール、Noto CJK フォント、Mozc）、NetworkManager、Firefox ESR、Flatpak。 |
| DT-02 | 量子回路スタジオ | 回路 JSON 版1の作成・編集（ゲートの追加・削除・並べ替え、rx/rz の角度）、回路図、ファイルの読み書き、サンプル、`qosctl` による検証・実行・停止、観測回数の表とグラフ、量子サービスの状態表示。 |
| DT-03 | 量子OS 更新マネージャー | `qos-admin update-status` の表示（確定スロット・試行先・状態・直近の失敗の説明）、更新バンドルの選択と適用、再起動の案内。管理者認証（polkit）を経て実行する。 |
| DT-04 | 開発環境セットアップ | 利用者が取得した IntelliJ IDEA の配布物（tar.gz）を利用者領域へ展開し、起動項目を作成し、OS 同梱の量子OSプラグインを導入する。利用規約への同意は利用者が IDE の初回起動時に行う。 |
| DT-05 | 健全性確認の拡張 | 試行起動の健全性確認に表示マネージャー（GDM）の稼働を加える。 |

## 3.1 量子回路スタジオ（DT-02）

- 量子サービスへは標準 CLI（`/usr/bin/qosctl`）を子プロセスとして呼び出す。引数は個別に渡し、シェルを介さない。ソケットへ直接接続しない（QIDE-FD 7章と同じ契約）。
- 終了値 0 は標準出力 1 行の結果 JSON、2／3／4 は標準エラー 1 行のエラー JSON として扱い、code で案内を出し分ける。BUSY は再試行しない。
- 編集中の回路は、量子サービスと同じ検証規則（`quantumos.circuit`）で即時に確認し、問題を一覧表示する。最終判定は量子サービスが行う。
- 結果・シードは画面にのみ保持し、利用者が明示した場合だけ保存する。
- 実行中は停止でき、停止後に届いた結果は採用しない。

## 3.2 量子OS 更新マネージャー（DT-03）

- `pkexec` で固定の補助プログラム `/usr/libexec/quantumos/qos-update-helper` を起動し、補助プログラムが `qos-admin --json update-status`／`qos-admin --json update BUNDLE` だけを実行する。引数は `status` と `apply 絶対パス` に限る。
- polkit の操作は第1引数で分ける。`org.quantumos.update.status`（状態表示）は管理者認証（`auth_admin_keep`）、ただしローカルで操作中の sudo グループの利用者は認証なしとする。`org.quantumos.update.apply`（適用）は毎回管理者認証（`auth_admin`）を要求する。
- `--json` 出力（QOS-FD で暫定）を読み、状態と失敗コードを日本語で説明する。
- 適用後は再起動を案内する（自動では再起動しない。QOS-IF 5章）。再起動は利用者の操作で行う。

## 3.3 開発環境セットアップ（DT-04）

- 配布物の `product-info.json` を読み、IntelliJ IDEA であること、ビルド番号がプラグインの互換範囲にあることを確認する。
- 展開先は `~/.local/opt/<製品>-<版>`、起動項目は `~/.local/share/applications/` に作る（管理者権限は使わない）。
- プラグインは IDE のプラグインディレクトリーへ展開する（IDE の初回起動前に導入）。プラグインの CLI パスは既定の `/usr/bin/qosctl` のまま使う。

# 4. 権限・データ・更新

| **項目** | **方針** |
|---|---|
| 権限 | アプリは利用者権限で動く。OS の更新だけ polkit 経由で root の `qos-admin` を起動する。 |
| データ | 回路・結果・シードを自動保存しない。ログに回路・結果を出さない。 |
| 更新 | デスクトップ版は製品 ID `quantumos-desktop` のバンドルだけを受け入れる。Flatpak のアプリと利用者データは A/B 更新・切り戻しで巻き戻らない。 |
| ネットワーク | 量子サービスは引き続きネットワーク待受をしない。Flatpak のリモートは既定で登録しない（管理者が追加する）。 |

# 5. 受入試験と改訂履歴

| **試験** | **期待結果** |
|---|---|
| T-DT-01 | デスクトップ版イメージが UEFI で起動し、GDM のログイン画面が出る。ルートは読み取り専用、`/var` は状態領域、`/etc` はオーバーレイ。 |
| T-DT-02 | 作成した利用者が `quantum` グループに属し、量子回路スタジオからベル回路を実行してキーが 00／11、合計が shots に一致する。 |
| T-DT-03 | 量子回路スタジオで、不正な回路の指摘、BUSY・停止・エラーの表示、明示保存以外に結果が残らないことを確認する。 |
| T-DT-04 | 更新マネージャーが管理者認証を要求し、状態を表示する。標準版の製品 ID のバンドルを拒否する。 |
| T-DT-05 | 開発環境セットアップが IDE を展開してプラグインを導入し、起動項目が表示される。管理者権限を使わない。 |
| T-DT-06 | 試行起動の健全性確認に GDM の稼働が含まれる。標準版のイメージ・試験結果は変わらない。 |
| T-DT-07 | GNOME の初期設定で作成した利用者が `quantum` グループに属する。GNOME ソフトウェアが OS のパッケージを更新しようとしない。 |
