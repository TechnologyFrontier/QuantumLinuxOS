# 1. 公開境界と対象環境

初版の評価対象はx86_64・UEFIの専用端末と仮想マシン。暫定構成は2仮想CPU以上（または同等の実機）、4
GiB RAM、32 GiB以上の専用ディスク。Secure
Bootは無効とした評価に限る。いずれも動作未確認。

| **境界**    | **対象・契約**                                                                                                      |
|-------------|---------------------------------------------------------------------------------------------------------------------|
| 標準CLI     | qosctlを利用者向けの入口とする。ローカル端末で実行。C++／JavaScript／Python／Rustの公開バインディングは提供しない。 |
| ローカルIPC | Unixドメインソケット /run/quantumos/quantum.sock。計算用の版付きJSON。HTTP、リモート接続、WebAssemblyは提供しない。 |
| 回路JSON    | 回路JSON版1は引き続き交換用。IPCメッセージの版とは独立し、回路内に実行用seedを含めない。                            |
| 管理境界    | 管理者だけがローカル更新ツールとシステム管理機能を使う。計算ソケットに更新操作は公開しない。                        |

## 1.1 版と整合

本設計はQOS-BDの対象環境とQOS-FDのOS-01〜OS-07に対応。未対応のIPC整数版はPROTOCOL_UNSUPPORTED、未対応の回路JSON整数版はSCHEMA_UNSUPPORTEDとして区別する。

# 2. 標準CLI（OS-03〜05）

| **コマンド**                               | **入力・結果**                                                                                                                       |
|--------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------|
| qosctl validate FILE                       | FILEを呼び出し元の権限で読み、実行可能な回路構造と終端測定を検証。成功時はJSONでvalidを返す。実行基盤の20量子ビット上限はrunで確認。 |
| qosctl run FILE \[--shots N\] \[--seed S\] | 回路を実行。Nは既定1,024、範囲1〜100,000。Sは0〜2⁶⁴−1の正規なASCII 10進表記。フラグ省略で自動生成。                                  |
| qosctl status                              | サービスに接続し、readyまたはbusyを返す。OS全体の健全性判定ではない。                                                                |

qosctl validate circuit.json  
qosctl run circuit.json --shots 8 --seed 0  
qosctl run circuit.json \# 省略時はOS由来の乱数種を使う

成功時は終了値0で結果オブジェクトのJSONを標準出力へ1行。失敗時は失敗コードとメッセージのJSONを標準エラー出力へ1行とし、部分結果は出力しない。例は設計上の利用例であり、コマンド実装は未提供。

| **終了値** | **区分**                                                  |
|------------|-----------------------------------------------------------|
| 2          | CLI引数、回路、形式、版、実行オプション、実行上限の違反。 |
| 3          | 接続不能、権限拒否、利用可能な計算枠なし。                |
| 4          | 計算失敗、期限超過、途中切断または応答不正。              |

# 3. IPCの転送と回路形式（OS-02〜05）

ソケットはストリーム型。サーバーは1接続で先頭の1フレームだけを処理し、応答後に閉じる。フレームは4バイト符号なしビッグエンディアンの長さに、指定長のUTF-8
JSONを続ける。要求・応答の本文は各1バイト〜8
MiB（暫定）。上限外の長さや切り詰めフレームは処理せず接続を閉じる。回路JSON自体は別にUTF-8で4
MiB以下。

ソケットは管理者所有・quantumグループとしモード0660を案とする。親ディレクトリーの置換を一般利用者に許可しない。サービスはOSの接続元資格情報と利用者の許可設定を確認し、要求本文の自己申告を信頼しない。

{"protocol_version":1,"op":"run","circuit":{  
"schema_version":1,"n_qubits":2,"operations":\[  
{"op":"x","qubits":\[1\]},  
{"op":"measure","qubits":\[1,0\]}\]},"shots":8,"seed":"0"}

要求ルートの必須項目はprotocol_version（整数1）、op（validate／run／status）。validateとrunにはcircuitが必須、shotsとseedはrunだけで省略可。statusは版と操作のみ。未知キー、重複キー、不正UTF-8・非有限値は拒否する。circuitの4
MiBは要求に含まれる回路オブジェクトのUTF-8バイト列で判定する。CLIはファイルの入力サイズも確認する。

回路版1はschema_version・n_qubits・operationsが必須。命令はopとqubitsが必須。rx/rzのみ有限ラジアン値thetaを持つ。ゲート集合はh/x/z/rx/rz/cx/measure。構造制約と実行上限は機能設計書2章に従う。

# 4. IPC応答・エラー・シード

{"protocol_version":1,"ok":true,"result":{  
"counts":\[\["10",8\]\],"shots":8,"seed":"0",  
"measured_qubits":\[1,0\],"backend_id":"local_statevector",  
"service_version":"0.1.0"}}  
{"protocol_version":1,"ok":false,"error":{  
"code":"RUN_OPTION_INVALID","message":"Invalid seed"}}

応答の必須項目はprotocol_version（整数1）とok（真偽値）。成功時だけresult、失敗時だけerrorを含む。validate成功は
{"valid":true}、status成功は {"state":"ready"} または {"state":"busy"}
をresultに格納する。runのcountsは［ビット列、正の整数回数］の配列で辞書順。シードは成功時必須。

| **コード**                             | **条件**                                                                     |
|----------------------------------------|------------------------------------------------------------------------------|
| PROTOCOL_INVALID／PROTOCOL_UNSUPPORTED | 要求のJSON・項目が不正／未対応のIPC整数版。                                  |
| CIRCUIT_INVALID／SCHEMA_UNSUPPORTED    | 回路の構造・回路版の型・測定規則が不正／未対応の回路整数版。                 |
| RUN_OPTION_INVALID／BACKEND_LIMIT      | shotsまたはseedが不正／量子ビット実行上限を超過。                            |
| ACCESS_DENIED／BUSY                    | 認可不成立／計算枠使用中。OSが接続を拒否した場合はCLIがACCESS_DENIEDを報告。 |
| TIMEOUT／EXECUTION_FAILED              | 実行期限超過／計算・資源確保・乱数取得の失敗。                               |
| SERVICE_UNAVAILABLE／TRANSPORT_ERROR   | CLI側の接続不能／途中切断・不正応答。                                        |

seedはASCII数字1〜20字で、0以外に先頭ゼロ不可。負数・符号・空白・指数・JSON数値・null・上限超過を拒否。例：最大値は「18446744073709551615」。エラーのmessageは診断用で、分岐にはcodeを使う。

# 5. 管理インターフェースと改訂履歴

| **管理操作（提案）**    | **権限・動作**                                                                                                 |
|-------------------------|----------------------------------------------------------------------------------------------------------------|
| qos-admin update BUNDLE | 管理者のみ。バンドルを検証し非稼働スロットに書き込む。成功は次回試行の予約まで。実行中のOSを自動再起動しない。 |
| qos-admin update-status | 管理者のみ。確定スロット、試行先（未予約ならなし）、状態と直近失敗コードを表示。                               |
| ローカル管理コンソール  | サービス停止・ログ確認と、試行先の障害時の復旧。管理機能は計算ソケットへ追加しない。                           |

更新マニフェストは最低限、製品ID、アーキテクチャ、対象版、イメージハッシュと署名を検証する。正式なバンドル構造、署名方式、管理CLIの機械可読出力、接続読み取り期限、ソケットの具体的な管理設定は結合前の確定事項。
