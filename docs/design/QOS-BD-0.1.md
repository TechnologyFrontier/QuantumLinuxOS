# 1. 製品範囲と対象環境

量子OS（設計上の呼称）は、Linuxカーネルと既存のユーザー空間を再利用し、量子回路シミュレーターを標準サービスとして組み込む。カーネル自体の新規開発や、量子実機の制御用ドライバーは初版の範囲に含めない。

初版の評価対象はx86_64・UEFIの専用端末と仮想マシン。暫定構成は2仮想CPU以上（または同等の実機）、4
GiB RAM、32 GiB以上の専用ディスク。Secure
Bootは無効とした評価に限る。いずれも動作未確認。

| **項目** | **方針**                                                                                                                                                     |
|----------|--------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 基盤OS   | Debian系の固定ベースを採用候補とする。ディストリビューションの具体版、カーネル系列、ハードウェアと仮想化方式は評価前に固定。                                 |
| 提供形態 | 起動可能なディスクイメージとオフライン更新バンドル。専用ディスクに展開して使う。既存OSとの併存インストーラーは初版対象外。                                   |
| 利用者   | ローカル管理者が導入・更新。一般利用者が標準CLIで回路を検証・実行。GUIは提供しない。                                                                         |
| 対象外   | Windows・macOS上へのネイティブ導入、arm64、物理量子機器、クラウド実行、ノイズ、外部ネットワークAPI。Windows・macOSは仮想化ホストとしても検証対象に含めない。 |

従来のWindows・macOS・UbuntuはSDKの対応候補であり、本版の対応OS表には引き継がない。C++は計算コアの実装候補。ブラウザーやWebAssemblyは標準実行経路に含めない。

# 2. システム構成と機能分担

| **層／構成**         | **責務**                                                                           | **機能ID** |
|----------------------|------------------------------------------------------------------------------------|------------|
| UEFI・ブートローダー | 起動先スロットを選ぶ。試行起動に失敗したら確定済みスロットへ戻す。                 | OS-01／06  |
| Linux・システム管理  | ファイルシステム、OS利用者・グループ、ローカルIPC、サービス起動と資源制限。        | OS-01／02  |
| 量子サービス         | 回路検証・状態ベクトル計算・測定、シード管理。専用の非特権アカウントで実行。       | OS-03〜05  |
| 標準CLI              | 回路ファイルを利用者権限で読み、ローカルソケットに送信。結果を標準出力へ返す。     | OS-03〜05  |
| 保守・診断           | 管理者が更新署名を検証して非稼働スロットへ適用。運用状態と最小限の診断情報を確認。 | OS-06／07  |

## 2.1 通常時と障害時の経路

通常経路：UEFI → 起動用領域 → Linux → システム管理 → 量子サービス →
CLI。管理経路：ローカル管理者 → 更新ツール → 非稼働スロット → 再起動 →
健全性確認。量子サービスの停止だけでOS全体を停止させず、管理コンソールから診断できる構成とする。

## 2.2 信頼境界とデータ

量子サービスはネットワーク待受を行わず、OSの利用者資格情報とソケット権限でアクセスを制御する。回路・測定結果は標準では永続化しない。ログはエラーコード、所要時間、件数に絞り、回路・結果・シードを含めない。

# 3. 起動・更新・資源方針

| **設計項目** | **方針**                                                                                                                                  |
|--------------|-------------------------------------------------------------------------------------------------------------------------------------------|
| ディスク構成 | EFIシステム領域、ルートA/B、状態領域を分離する。通常起動中のルートは読み取り専用。利用者ホームと更新状態は状態領域に分ける。              |
| 更新         | 配布元の公開鍵をイメージに配置し、更新マニフェストの署名とイメージのハッシュを検証。稼働中のルートは書き換えない。                        |
| 切り戻し     | 試行先で期限内に健全性確認できなければ、次回起動で確定済みルートへ戻す。切り戻しは状態領域の利用者データを巻き戻さない。                  |
| 初版の制約   | 評価構成ではSecure Boot無効。更新署名の検証は起動チェーンやディスク改変への耐性を保証しない。物理アクセス保護とディスク暗号化は別途設計。 |
| 計算資源     | サービス全体で計算は同時1件、待ち行列なし。初期値としてメモリ上限512 MiB、実行期限120秒を設定し、評価後に調整。                           |

回路仕様：構造上1〜64量子ビット、測定込み最大10,000命令。実行上限は20量子ビット、ショット数は1〜100,000（既定1,024）。回路JSONはUTF-8換算4
MiB以下。

## 3.1 既存資産の引き継ぎ

ゲート集合、終端測定、回路JSON版1、64ビットシードの値域は引き継ぐ。公開契約はOSのCLIとローカルIPCに切り替え、以前のSDK
APIや実行基盤との出力一致は保証しない。

# 4. 受入方針と決定事項

| **対象**     | **受入観点**                                                                                                 |
|--------------|--------------------------------------------------------------------------------------------------------------|
| OS起動・権限 | 対象実機と仮想機で起動。サービス非稼働でも管理コンソールへ入れる。未許可利用者を拒否し、非特権で計算が動く。 |
| 量子機能     | 決定的回路・測定順・回路JSON往復・シード境界・同一環境での再現性を確認。                                     |
| 更新・障害   | 正規更新、改変バンドルの拒否、健全性失敗時の切り戻し、状態領域の保持、実行期限と過負荷を確認。               |

## 4.1 実装前の確認事項

基盤OSとカーネルの具体版、評価する実機・仮想化環境、イメージ作成方式、署名方式・鍵更新、ブート試行回数の永続化、資源上限と性能基準を確定する。機能設計書は動作と受入試験、インターフェース仕様書はCLI・ローカルIPCの契約を定義する。
