# 1. OS起動と利用権限（OS-01／02）

初版の評価対象はx86_64・UEFIの専用端末と仮想マシン。暫定構成は2仮想CPU以上（または同等の実機）、4
GiB RAM、32 GiB以上の専用ディスク。Secure
Bootは無効とした評価に限る。いずれも動作未確認。

| **機能**       | **前提・処理・結果**                                                                                                                                                                  |
|----------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| OS-01 通常起動 | 選択したルートスロットを読み取り専用でマウントし、状態領域、ローカルログイン、量子サービスを順に初期化する。                                                                          |
| OS-01 起動失敗 | ルートまたは必要な状態領域のマウントに失敗した場合は通常サービスを始めない。確定済みスロットでの回復方法は管理コンソールまたは保守メディアで実施する案。試行起動はOS-06の判定を適用。 |
| OS-02 認可     | 専用グループquantumの利用者にソケット接続を許可し、サービスでも接続元UIDと許可を照合。管理操作はOS管理者に限定し、計算ソケットからは実行できない。                                    |
| OS-02 分離     | 計算サービスは専用の非特権アカウント。利用者のファイルパスを受理せず、CLIから回路の内容だけを受け取る。ネットワーク待受は行わない。                                                   |

## 1.1 稼働状態

量子サービスが起動・停止・異常終了しても、OSのローカル管理コンソールは独立して使える。標準CLIのstatusは、サービスに接続できればreadyまたはbusyを返す。接続不能はローカルエラーとして扱う。

# 2. 回路検証・実行・結果（OS-03〜05）

回路仕様：構造上1〜64量子ビット、測定込み最大10,000命令。実行上限は20量子ビット、ショット数は1〜100,000（既定1,024）。回路JSONはUTF-8換算4
MiB以下。

| **機能**       | **処理と出力**                                                                                                                                               |
|----------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------|
| OS-03 検証     | 回路JSON版1を解析。必須キー、未知キー、重複キー、数値・ビット範囲、ゲート引数、命令数、測定位置を確認。validate／runは終端測定が必須。                       |
| OS-04 実行制御 | 認可 → メッセージ検証 → 回路 → shots → seed → 実行上限 → 空き枠確認 → 乱数種の決定 → 計算。計算枠は全利用者で同時1件、待ち行列なし。                         |
| OS-04 実行計算 | 複素倍精度で全ゼロの基底状態からH、X、Z、RX、RZ、CXを順に適用。量子ビット0は基底インデックスの最下位ビット。測定対象外を周辺化し、確率分布から復元抽出する。 |
| OS-05 結果     | 指定順の測定ビット列と観測回数を返す。観測済みのみ辞書順で返し、合計はshots。成功結果には実際のseedを必ず含める。                                            |

## 2.1 シードと再現性

seedは0〜2⁶⁴−1の正規なASCII
10進文字列。省略時は実行上限と空き枠を確認後にOSの乱数源から取得し、明示ゼロと区別する。回路JSONにseedは入れない。同一OSイメージ・サービスビルド・実行環境・回路・shots・seedで観測回数の一致を受入条件とし、環境間の一致は保証しない。乱数手順の詳細は実装前に固定する。

## 2.2 実行中断

実行期限の初期値は120秒。期限超過や資源不足は部分結果を返さない。接続切断時は計算の停止を要求し、ワーカー終了を確認してから枠を解放する。

# 3. 更新・復旧・診断（OS-06／07）

| **段階** | **処理・終了条件**                                                                                                                                        |
|----------|-----------------------------------------------------------------------------------------------------------------------------------------------------------|
| 更新前   | 管理者がバンドルを指定。マニフェスト署名、対象製品・アーキテクチャ、版、イメージハッシュ、空き容量を確認。不合格なら稼働中スロットを変更しない。          |
| 書き込み | 非稼働ルートへ書き込んで再照合。検証完了後にだけ次回試行フラグを設定。更新書き込み中断では従来の確定済みルートから起動する。                              |
| 試行起動 | 起動可能なルート、状態領域、管理コンソール、量子サービスの自己診断を確認。自己診断は内部で1量子ビットの決定的回路を実行する。合格時のみ試行先を確定する。 |
| 切り戻し | 試行に失敗または期限超過した場合は確定済みスロットを次回起動先に戻す。利用者データは変更しない。試行回数・監視期限・永続化方式は結合前に確定。            |
| 診断     | 管理者が起動スロット、更新状態、サービスの稼働を確認。ログは所要時間、命令数、ショット数、エラーコード中心。回路、測定結果、シードは記録しない。          |

更新状態は「確定済み → 試行予約 → 試行中 →
確定済みまたは切り戻し」。同時更新は受理しない。初版では状態領域に旧版から戻せない形式変更を行わない。

# 4. 受入試験と改訂履歴

| **試験／対象**     | **入力・期待結果**                                                                                         |
|--------------------|------------------------------------------------------------------------------------------------------------|
| T-OS-01／OS-01     | 対象実機・仮想機で起動し、CLIと管理コンソールが利用可。量子サービスを停止しても管理コンソールは利用可。    |
| T-OS-02／OS-02     | 許可・未許可利用者を切り替え、許可利用者だけが実行可。一般利用者が更新できず、ネットワーク待受がない。     |
| T-OS-03／OS-03〜05 | 回路JSONの版、上限、重複キー、終端測定を検証。X(1)→measure(1,0)で「10」のみ返る。                          |
| T-OS-04／OS-04/05  | 0、2⁵³＋1、2⁶⁴−1を文字列で往復。上限超過・不正形式の拒否、省略時の返却、再実行の一致を確認。               |
| T-OS-05／OS-04     | 同時要求でBUSY、期限超過でTIMEOUT。部分結果なし。終了後に後続要求を実行可。                                |
| T-OS-06／OS-06/07  | 正規更新、改変バンドル、書き込み中断、試行起動失敗を個別確認。失敗時も確定済みルートと利用者データを保持。 |
